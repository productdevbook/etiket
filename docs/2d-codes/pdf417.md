# PDF417

ISO/IEC 15438. A stacked linear symbology: rows of 17-module codewords, each row
bracketed by start and stop patterns and row indicators. "417" is the structure —
4 bars and spaces per codeword, 17 modules wide.

## When to Use It

- Government identity documents: US and Canadian driving licences, visas
- Boarding passes and transport tickets
- Shipping labels, where a large payload must survive a scuffed label

## Usage

```ts
import { pdf417, encodePDF417 } from "etiket"

// Convenience function — returns SVG
pdf417("Hello World")
pdf417("Data", { ecLevel: 4, columns: 5, compact: true })

// Raw encoder — returns { matrix, rows, cols }
const result = encodePDF417("Hello, World!")
result.rows // 18
result.cols // 86
```

A sub-path export covers PDF417 and MicroPDF417:

```ts
import { pdf417, encodePDF417 } from "etiket/pdf417"

pdf417("Hello")
encodePDF417("Hello")
```

## Capacity and Constraints

| Property         | Range                                     |
| :--------------- | :---------------------------------------- |
| Data codewords   | 1 – 925                                   |
| Data columns     | 1 – 30 (`columns`)                        |
| Rows             | 3 – 90 (chosen from the data and columns) |
| Error correction | Levels 0 – 8, 2 to 512 EC codewords       |

Those 925 codewords hold up to **2710 digits**, **1850 text characters** or
**1108 bytes**, depending on which compaction mode the data allows. Anything
beyond raises `CapacityError`.

## Options

| Option    | Type      | Default | Description                                    |
| :-------- | :-------- | :------ | :--------------------------------------------- |
| `ecLevel` | `0-8`     | auto    | Error correction level                         |
| `columns` | `1-30`    | auto    | Number of data columns                         |
| `compact` | `boolean` | `false` | Compact PDF417 — omits the right row indicator |
| `eci`     | `number`  | auto    | ECI assignment number for the data             |

When `ecLevel` is omitted it is chosen from the payload size, following the
recommendation in the standard:

| Data codewords | EC level | EC codewords |
| :------------- | :------- | :----------- |
| ≤ 40           | 2        | 8            |
| ≤ 160          | 3        | 16           |
| ≤ 320          | 4        | 32           |
| ≤ 863          | 5        | 64           |
| more           | 6        | 128          |

`pdf417()` additionally takes `width` (overall symbol width in pixels, default
`400`) and `height`, on top of the
[shared matrix rendering options](/2d-codes/#shared-rendering-options).

```ts
import { pdf417 } from "etiket"

pdf417("Hello", { width: 600, margin: 2, color: "#1d3557" })
```

## Compaction Modes

The encoder switches between the three compaction modes of the standard as the
data changes:

| Mode    | Rate              | Covers                             |
| :------ | :---------------- | :--------------------------------- |
| Text    | 2 characters / CW | Printable ASCII, in five sub-modes |
| Byte    | 1.2 bytes / CW    | Any byte                           |
| Numeric | ~2.9 digits / CW  | Long digit runs                    |

A lone byte inside text — an accented letter in an otherwise ASCII string — is
shifted into rather than latched, so it costs two codewords instead of four.
Where the accents come thick enough that byte compaction over the whole stretch
is shorter, the encoder uses that instead.

Text outside ISO-8859-15 is emitted as UTF-8 bytes under an automatic ECI 26
declaration; `eci` declares a character set explicitly.

```ts
import { encodePDF417 } from "etiket"

encodePDF417("日本語") // UTF-8 under ECI 26, automatically
encodePDF417("Grüße", { eci: 3 }) // declared as ISO-8859-1
```

## PNG

```ts
import { pdf417PNG, pdf417PNGDataURI } from "etiket"

pdf417PNG("Hello", { moduleSize: 4, rowHeight: 3 })
pdf417PNGDataURI("Hello")
```

PDF417 rows are conventionally 3 times the module width; pass `rowHeight` to
match your printer's aspect ratio.

## Caveats

- `compact: true` drops the right row indicator. It saves modules but not every
  reader accepts it — check your fleet first.
- `columns` is a hard constraint. A narrow symbol with a large payload runs past
  the 90-row limit and raises `CapacityError`.
- An `ecLevel` outside 0–8 raises `InvalidInputError`; empty input does too.
- See [MicroPDF417](/2d-codes/micropdf417) for the compact variant with 1–4
  columns and no start/stop patterns.

## CLI

```bash
etiket pdf417 "Hello" -o pdf417.svg
etiket pdf417 "Hello" --ec-level 4 --columns 5 -o pdf417.png
```
